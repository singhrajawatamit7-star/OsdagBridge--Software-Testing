# QA Release & Submission Checklist

## Release decision

**Status: CONDITIONALLY VERIFIED QA PORTFOLIO; NOT FULLY RELEASE-APPROVED.** This repository contains useful QA assets, but a clean release requires a fresh local/CI run and evidence review. A passing QA-framework test does not mean the upstream OsdagBridge application is defect-free.

## Required gates

- [ ] Install dependencies from a clean environment using `python -m pip install -r requirements.txt`.
- [ ] Pin and verify the official OsdagBridge source revision used by the tests.
- [ ] Run `python -m pytest tests -v --tb=short --junitxml=reports/test_results/junit.xml`.
- [ ] Export results with `python scripts/export_junit_csv.py reports/test_results/junit.xml test_results.csv --strict`.
- [ ] Confirm CSV outcome counts match the JUnit XML: PASS, FAIL, ERROR, XFAIL and SKIPPED reported separately.
- [ ] Confirm the dashboard reads the same generated CSV and never substitutes hard-coded test counts.
- [ ] Review every strict XFAIL against an open upstream defect and verify that unexpected passes fail CI.
- [ ] Execute the manual test plan against the real desktop application; mark inaccessible workflows BLOCKED, not PASS.
- [ ] Replace SVG wireframes/mockups with genuine, dated application screenshots where visual evidence is claimed.
- [x] Verify the defect register contains unique IDs OB-BUG-001 through OB-BUG-016 and distinguishes official-app defects from QA-reference utility findings.
- [x] Confirm GitHub Actions succeeded on every configured OS/Python matrix entry for commit `d6759d22995acea5cf152c88a36c3ef9af42767f` (run [45010909943](https://github.com/singhrajawatamit7-star/OsdagBridge--Software-Testing/actions/runs/45010909943)); re-check after any new commit.
- [x] Align documented inventory and defect totals; historical test timestamps are explicitly labelled as historical.

## Scope and evidence rules

- `osdagbridge_core` is an independent QA/reference utility. Its tests do not establish that the official application works.
- Tests that observe placeholder/stub behavior are defect-reproduction tests, not successful functional verification.
- XFAIL means a known expected failure; SKIPPED means a test did not execute. They are not interchangeable.
- A CI artifact or committed CSV is historical evidence. It must not be described as a fresh run unless generated by the current execution.
- Upstream defects remain open until verified fixed in the official OsdagBridge repository.

## Sign-off

Do not use a “Submission Ready” badge until every required gate above has been checked with current evidence. The repository may be submitted as a QA portfolio with its limitations clearly disclosed, but the target application remains conditionally blocked by open upstream issues.
